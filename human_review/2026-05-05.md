# 2026-05-05 notes and observations

I've not done much today in terms of using AI as I hit my weekly Codex rate
limits the other day. I'm only on a Plus subscription for now. A Plus
subscription is giving me somewhere between 5 and 10 hours usage per week. If
the agent is in a tight loop I can run out my 5 hour limit in less than an hour.
I should probably try testing out other models as I have mainly been using
GPT-5.4

I have also done a bit of experimenting with Google's Gemini CLI using their
free tier, but I'm finding that it very quickly hits rate limits (withing a few
minutes, if that). Authentication with Gemini CLI is better in my opinion as
you can just use an API token (which iirc has the same limits as if you log
in with your Google Account). Codex needs an oauth login, which then requires
you to use a browser based flow (which is a pain if you want to run in a
minimal VM). Note I'm using these AI coding agents in a VM as I do not trust
running them on my local machine. At the moment I am using a very simple means#
of getting code out of the vm. Basically I'm using nc:

Host:
```
nc -w 1 -l 8000 > out.tar
```
VM:
```
tar cvf out.tar source_code/
nc 10.0.2.2 8000 < out.tar
```
This is primitive but effective. The better way would probably be to just run
ssh on the VM, and then doing a git pull on my local machine via a ssh URL to
the VM. There is then a command to push up to github from my host machine.

Pricing for Codex seems quite vague to me. There is no direct mapping between
what I pay for Plus, and how many tokens I am using. Extra tokens can be bought
for £40 per 1000 (and they do publish their per token rates) but it's not clear
whether it would be cheaper to upgrade to Pro, or top up with credits. My
suspicion is that currently it's cheaper to just get a Pro subscription to
increase my usage as bundled subscription usage is (currently) vastly cheaper
than the token costs. This pricing may change in the near future as demand
increases. Also worth keeping an eye on how quickly I burn through my codex
rate limit, I wonder if it will gradually start burning more quickly over time.

I should maybe get some other cheap subscriptions and compare different models
from different providers. I would also like to look into local models, but I
don't currently have any hardware powerful enough to run them. Maybe I should
look at some smaller specialised models (on the basis that some of the more
useful open weight general models are pretty large).

One useful aspect of having to limit how much I use AI per day is that I have
time to review what the AI is actually doing. For my current test projects I
have been trying to get the AI to write code and documentation that can be
reviewed by a human. I have mostly skimmed the code, but I plan to review more
deeply as I can see some subtle issues.

General observation about AI agent coding is that it does seem to be at the
point where it can pretty effectively write and debug code. I've limited
experience of the earlier models, but from what I've seen and experienced of
the earlier models they do seem to have been much weaker. For example, I was
experimenting with Claude Haiku 4.5 on Github and it was useless, it could
barely follow instruction and would constantly make mistakes and generate
nonsense code. With Codex and GPT-5.4 it is vastly better (to the point where
it is surprising how well it can write and debug code). GPT-5.4 does seem to
behave like a fairly competent (and very knowledgeable) software engineer. I
have found that I do have to give it some useful insights to unblock it when
it starts getting stuck in a loop, or goes off in a tangent trying to solve a
problem in a convoluted way. I think one of the problems is that it can
successfully solve problems in convoluted ways, but it doesn't always have the
sense to try and avoid convoluted solutions. It seems like I'm managing a
engineer that can work very quickly, but who needs to be given effective
direction to avoid it wasting time spinning it's wheels.
