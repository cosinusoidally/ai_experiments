mawkcc_self.c readability next steps
====================================

Remove each item from this file once it has been completed and verified.

1. Split builtin classification into helper predicates.

   `builtin_arity()` currently contains deeply nested `or(or(...))`
   expressions. Add readable helpers such as:

       is_builtin1(name)
       is_builtin2(name)
       is_builtin3(name)

   Then make `builtin_arity()` return 1, 2, 3, or 0 using those helpers.
   Keep the helper contents aligned with the `strcmp` groups in
   `mawkcc_orig.c`.

2. Add short accessor helpers for pointer-backed arrays.

   Many call, relocation, break, and data-patch arrays are accessed with
   repeated expressions such as:

       ri32(add(call_target_p, mul(i, 4)))
       wi32(add(reloc_types_p, mul(reloc_count, 4)), type)

   Add short getter/setter functions following the existing `sym_name`,
   `sym_val`, `sym_set_name`, and `sym_set_val` style. Candidate groups:

       call_target/call_pos/call_argc
       reloc_offsets/reloc_names/reloc_types
       break_patch_loop/break_patch_pos
       data_patch_offsets/data_patch_addends
       current_params/current_param_offsets

3. Replace raw allocation byte counts in `init_globals()`.

   The self side currently allocates raw byte counts such as `32768`,
   `16384`, and `4096`. These correspond to fixed capacities and element
   widths from `mawkcc_orig.c`, for example `MAX_SYMS`, `MAX_RELOCS`,
   `MAX_PARAMS`, `MAX_BREAKS`, and `MAX_LOOPS`.

   Introduce readable initialized globals or helper functions such as:

       max_syms = 4096;
       globals_p = xmalloc(mul(max_syms, 8));

   Do not extend the mawkcc dialect.

4. Add named fail wrappers around `fail_code()`.

   Calls such as `fail_code(17, 0)` are hard to audit. Add small wrappers
   for common cases so the call sites describe intent, while preserving the
   current simple diagnostics. Examples:

       fail_missing_main()
       fail_relocation_overflow()
       fail_break_outside_loop()
       fail_unknown_identifier(name)

   Keep the wrappers close in meaning to the corresponding `failf()` calls
   in `mawkcc_orig.c`.

5. Split `build_object_()` into smaller phases.

   `build_object_()` currently has a large local-variable workaround and is
   difficult to review. Split it into smaller helpers that mirror the
   conceptual blocks in `mawkcc_orig.c`:

       layout calculation
       ELF/header emission
       section contents emission
       section table emission

   This is higher risk than the previous items and should be done only with
   full byte-identity verification.

6. Normalize dense multi-byte opcode emitters.

   Some emitter helpers are dense one-liners, especially multi-byte
   instruction sequences such as:

       emit_epilogue
       emit_shl_ebx_by_eax
       emit_shr_ebx_by_eax
       emit_div_stack_top_by_eax
       emit_mod_stack_top_by_eax

   Expand or lightly structure these where it improves auditability. Keep the
   emitted byte order visibly aligned with `mawkcc_orig.c`.
